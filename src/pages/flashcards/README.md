# Учи.Карточки

Семь экранов по handoff, React Router + существующий QueryProvider, CSS Modules.
Приблизительные токены палитры из DESIGN_SYSTEM.md; сверка с точным Figma-экспортом остаётся TODO.

## Локальный запуск

Backend должен работать на localhost:8080 с применённой dev-миграцией.

```bash
pnpm install
cp .env.example .env.development.local
pnpm dev
```

Открыть `/quizlet`. Повторно запускать `init-template` не требуется.
Запросы идут через существующий Vite proxy `/api/v1`.
`VITE_DEV_USER_ID` добавляется только серверным dev-прокси при development mode,
пути `/api/v1` и localhost target. Клиент не передаёт ID пользователя.
После изменения env перезапустите Vite полностью: базовый конфиг сохраняет env в process.env.

## Что работает

- Библиотека собственных наборов и черновиков, страницы по 50 наборов.
- Ручное создание, название, вопросы/ответы, добавление/удаление, редактирование и удаление набора с подтверждением.
- Отдельное сохранение черновика на сервере; восстановление несохранённых правок в sessionStorage текущей вкладки по ID и ревизии. Конфликт ревизий возвращает 409.
- Тренировка: tap / Enter / Space переворачивают, swipe left = unknown, right = known, стрелки клавиатуры дают ту же оценку на обеих сторонах.
- Вертикальный жест и pointercancel не оценивают. Одновременные указатели и повторные действия блокируются.
- При сетевой ошибке повторяется тот же eventId, без перехода к следующей карточке до подтверждения сервера.
- Долговременные статусы знания и сессии хранятся в PostgreSQL, восстанавливаются после reload.
- Завершение занятия, реальные результаты, повторное занятие. Выход раньше конца явно показывает пройденное число.

## Фото / текст: заглушка

`VITE_DEMO_GENERATION=true` работает **только в development**. При выборе одного JPG/PNG до 10 МБ либо текста до 20 000 символов показываются 3 фиксированные карточки, независимо от выбранных 10/20/30. Это явно написано на экранах.
Фото остаётся в браузере; preview URL освобождается, файл не загружается на сервер. Исходный текст временно хранится в sessionStorage, очищается после создания черновика. Внешних OCR / LLM запросов в новом сценарии нет.
Production сборка блокирует генерацию даже с этим флагом. Ручной путь доступен.
Существующий ScanPage / Tesseract оставлен в исходниках как предыдущий эксперимент, но не подключён к маршрутам приложения.

## Production зависимости

Нужен утверждённый маршрут gateway `/api/v1` к quizlet-api и сопоставление проверенной платформой identity с доверенным `X-User-Id`. Прямой публичный доступ к backend с произвольным этим заголовком недопустим по контракту существующего HeaderAuth. Shaman / CI / схему авторизации эта реализация не меняет.
До подключения AI необходимо согласовать провайдера, серверные секреты, политику данных, загрузку/лимиты и валидацию фактов. Не помещайте ключи в VITE_*.

## Проверки

```bash
pnpm build
pnpm lint
pnpm test
```
Vitest 3.2.7 выбран для совместимости с Vite 6. Тесты: направления/порог жестов, вертикальный скролл, процент знания, валидация редактора, keyboard flip/grade, rapid duplicate, retry eventId, восстановление занятия, ограничение файла.

Проверка CI `pnpm audit --prod --audit-level=high` остаётся красной: 26 advisories (20 high, 5 moderate, 1 low).
Сравнены текущий и исходный HEAD lockfile: набор ID advisories одинаков, новых advisories нет.
Это требует отдельно согласованного обновления зависимостей шаблона перед production; audit job сохранён.
