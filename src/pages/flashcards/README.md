# Учи.Карточки

Семь экранов по handoff, React Router + существующий QueryProvider, CSS Modules.
Оформление сверено с [Figma quizlet](https://www.figma.com/design/XpSlJjfszfY1Hnil4GMfQt/quizlet?node-id=6-6045): семь экранов 6:6045–6:6395.
Градиент, палитра, размеры, отступы, радиусы, типографика и локальные оригинальные SVG перенесены в существующие Shell / Progress / Sprout и CSS Modules.
Макеты адаптированы к текущей методике: процент последней завершённой тренировки, освоенные карточки, повтор всего набора.
Профиль/отдельная страница прогресса и системные панели iOS не добавлены: этих маршрутов нет в продукте. Сохранены ручной/текстовый/фото ввод, черновики, редактирование и жесты.
Создание набора — широкая кнопка из нового макета; в тренировке есть неброские текстовые кнопки «‹ Не знаю» / «Знаю ›», работающие на обеих сторонах. Переворот — нажатием на карточку; отдельной кнопки «Показать ответ» нет. Оценки блокируются на время отправки и при ожидающем сетевом повторе.
Контент растягивает карточки при длинных ответах; используется safe-area, ширина контента до 480 px (тренировка до 440 px).

## Локальный запуск

Backend должен работать на localhost:8080 с применённой dev-миграцией.

```bash
pnpm install
cp .env.example .env.development.local
pnpm dev
```

Открыть `/quizlet`. Повторно запускать `init-template` не требуется.
Запросы идут через существующий Vite proxy `/api/v1`.
`VITE_DEV_USER_ID` добавляется только серверным dev-прокси при development mode,
пути `/api/v1` и localhost target. Клиент не передаёт ID пользователя.
После изменения env перезапустите Vite полностью: базовый конфиг сохраняет env в process.env.

## Что работает

- Библиотека собственных наборов и черновиков, страницы по 50 наборов.
- Ручное создание, название, вопросы/ответы, добавление/удаление, редактирование и удаление набора с подтверждением.
- Отдельное сохранение черновика на сервере; восстановление несохранённых правок в sessionStorage текущей вкладки по ID и ревизии. Конфликт ревизий возвращает 409.
- Тренировка: tap / Enter / Space переворачивают, swipe left = unknown, right = known, стрелки клавиатуры дают ту же оценку на обеих сторонах.
- Вертикальный жест и pointercancel не оценивают. Одновременные указатели и повторные действия блокируются.
- При сетевой ошибке повторяется тот же eventId, без перехода к следующей карточке до подтверждения сервера.
- Очередь повторов и промежуточные ответы хранятся в PostgreSQL, восстанавливаются после reload.
- Завершение только полностью разобранной очереди; выход до конца сохраняет место и предлагает продолжение, сохраняя прежний результат набора.

## Методика обучения

Два последовательных «Знаю» для карты дают mastered; «Не знаю» сбрасывает streak, третья неудача даёт needs_practice. Повторы — через три других показа, с приоритетом наступивших повторов. В малых наборах карты чередуются; единственная оставшаяся карта повторяется сразу. Максимум шесть ответов на карту исключает бесконечный цикл.
Следующий показ выбирает сервер (nextCardId / presentationIndex), клиент не исключает карту после первого ответа. eventId + presentationIndex обеспечивают одну оценку на показ.
Прогресс занятия — X из N освоено. В библиотеке — процент по последней **завершённой** сессии; до первой прочерк. Правка содержания/порядка/состава сбрасывает отображение прежнего результата, сохраняя историю. Переименование не сбрасывает процент.
После прерывания кнопка набора предлагает продолжить. Результат — mastered / snapshotTotal и needs_practice. Это самооценка воспоминания в текущей тренировке.
Старые занятия первого алгоритма сохранены в БД, но не считаются результатом новой методики.

## Шрифт

Factor A 400 / 700 / 900 через предоставленные static.uchi.ru woff2/woff/ttf. Глобальный sans-token и формы используют его; промежуточные веса сопоставлены реальным начертаниям, font-display: swap.

## Генерация из текста и фото

Текст до 20 000 символов передаётся существующему backend POST /api/v1/generations, который создаёт карточки через VK AI Proxy (diona-30b). 10/20/30 — желаемое количество: при малом числе фактов может быть меньше. Результат открывается в редакторе. Ошибки модели видны пользователю, источник сохраняется, demo fallback отсутствует.
Ключ хранится только на backend, никакого VITE_* ключа. Генерация текста доступна без demo-флага и в production сборке, когда backend настроен. Timeout клиента 85 секунд, backend 75 секунд.
Фото JPG/PNG до 10 МБ автоматически передаётся backend POST /api/v1/recognitions. Vision-модель gpt-5.4-mini распознаёт текст страницы на исходном языке. После появления текста можно продолжить к настройкам и создать карточки без перепечатывания. Текст доступен для просмотра/исправления. Ошибка блокирует продолжение и позволяет повторить распознавание; старые результаты после замены/удаления фото игнорируются. Фото не хранится в sessionStorage и не сохраняется backend; оно передаётся корпоративному AI Proxy для обработки.
Рабочий путь фото больше не использует demo-флаг или фиксированные карточки; доступен также в production сборке при настроенном backend.
Исходный/распознанный текст временно хранится в sessionStorage текущей вкладки при переходе к настройкам и очищается после создания черновика.
Существующий ScanPage / Tesseract оставлен как предыдущий эксперимент, но не подключён к маршрутам приложения.

## Production зависимости

Нужен утверждённый маршрут gateway `/api/v1` к quizlet-api и сопоставление проверенной платформой identity с доверенным `X-User-Id`. Прямой публичный доступ к backend с произвольным этим заголовком недопустим по контракту существующего HeaderAuth. Shaman / CI / схему авторизации эта реализация не меняет.
Подключение AI использует предоставленный пользователем корпоративный proxy. Для stage/prod секреты backend необходимо передать штатным механизмом платформы; deployment не менялся. Не помещайте ключи в VITE_*.

## Проверки

```bash
pnpm build
pnpm lint
pnpm test
```
Vitest 3.2.7 выбран для совместимости с Vite 6. Тесты: направления/порог жестов, вертикальный скролл, процент знания, валидация редактора, keyboard flip/grade, rapid duplicate, retry eventId, восстановление занятия, ограничение файла.

Проверка CI `pnpm audit --prod --audit-level=high` остаётся красной: 26 advisories (20 high, 5 moderate, 1 low).
Сравнены текущий и исходный HEAD lockfile: набор ID advisories одинаков, новых advisories нет.
Это требует отдельно согласованного обновления зависимостей шаблона перед production; audit job сохранён.
